# 6장 - 객체 지도

## 기능을 담을 구조가 필요하다

요구사항은 계속 바뀌지만, 그 안에서 다루는 개념과 관계는 상대적으로 오래 남는다.
이 구조를 표현하는 것이 도메인 모델이다. DB 테이블 목록만을 의미하는 건 아님.

| 재료 | 설명하는 것 |
| --- | --- |
| 도메인 모델 | 서비스에서 다루는 개념과 관계 |
| 유스케이스 | 사용자가 이루려는 목표와 시스템과의 상호작용 |
| 책임-주도 설계 | 목표를 이루기 위한 일을 객체들에게 나누는 방법 |

유스케이스로 필요한 일을 찾고, 도메인 모델에서 그 일을 맡길 객체를 찾아본다.
구조만 그리거나 실행 순서만 적는 데서 끝내지 말고 둘을 연결해야 함.
도메인 모델도 바뀔 수 있지만, 기능이 추가될 때마다 전체를 다시 만들지 않도록 기준이 되어준다.

## 설명하는 말과 코드의 이름

요구사항에서는 주문과 메뉴를 이야기하는데 코드에는 `DataManager`만 있으면 연결해서 읽기 어렵다.
**도메인에서 쓰는 말이 코드에도 남아 있으면** 어디를 살펴봐야 할지 짐작하기 쉽다.

바로 로직부터 작성하기 전에 사용자가 원하는 것과 관련된 개념들을 같이 적어봐야겠다.
