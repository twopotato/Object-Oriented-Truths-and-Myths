# 1장 - 협력하는 객체들의 공동체

**클래스를 많이 나누는 것만으로 객체지향적인 설계가 되는 건 아니다.**
실제로 객체들이 어떤 일을 맡고, 어떻게 요청을 주고받는지를 봐야 함.

## 역할, 책임, 협력

- 협력: 하나의 기능을 위해 객체들이 요청하고 응답하는 과정
- 책임: 각 객체가 알아야 하는 것과 해야 하는 것
- 역할: 협력 안에서 관련된 책임을 묶은 것

객체는 자신의 일을 책임지면서, 혼자 처리할 수 없는 부분은 다른 객체에게 요청한다.
자율적이라는 게 모든 일을 혼자 한다는 뜻은 아님.

## 클래스를 보기 전에

클래스는 객체의 상태와 행동을 코드로 표현하는 도구다.
파일은 잘 나뉘어 있는데 판단과 처리를 한 곳에서 전부 한다면, 나머지 객체는 값만 보관하고 있을 수 있다.

코드를 볼 때도 클래스 목록부터 보기보다 **요청 하나가 어떤 객체들을 거쳐 처리되는지** 따라가봐야겠다.
